# 선택 과제 노트북 제출과 피드백

기존 사이트의 Neon 프로젝트·브랜치에서 `db/migrations/008_project_submissions.sql` 전체를 SQL Editor에 붙여 넣고 실행합니다. 기존 선택 과제 테이블(007)이 있는 DB용이며, 008은 다시 실행해도 파일이나 피드백을 덮어쓰지 않습니다. 전체 `db/setup.sql`을 다시 실행할 필요는 없습니다. 추가 환경변수나 파일 저장 서비스는 필요하지 않습니다.

SQL 적용 전에도 기존 페이지는 계속 열리며 학생에게는 제출 준비 중, 관리자에게는 SQL 적용 안내를 표시합니다. 적용 후 페이지를 새로고침하면 사용할 수 있습니다.

- 학생: 공개된 과제의 해당 주차를 완료 → `.ipynb` 선택 → 업로드 → 피드백 요청.
- 관리자: `/admin` → 선택 과제 피드백(`/admin/submissions`) → 대기 중 목록에서 노트북 다운로드 → 간단한 피드백 저장.
- 학생: 선택 과제 페이지를 다시 열거나 새로고침하여 답변 확인. 메일 알림은 보내지 않습니다.

과제별·학생별 최신 노트북 하나를 Neon DB에 저장합니다. UTF-8 Jupyter Notebook 4 형식, 최대 3MiB(화면 표기 3MB)이며 코드와 실행 결과를 그대로 보존합니다. 모델 weight, 데이터셋, ZIP 파일은 받지 않습니다. 파일이 큰 경우 불필요한 대량 출력이나 이미지를 정리한 후 제출합니다. 저장 공간은 학생 수 × 과제 수 × 파일 크기에 따라 늘어납니다.

새 파일을 올리면 기존 파일과 요청·피드백을 교체하고 요청 전 상태로 돌아갑니다. 학생이 다시 피드백 요청을 눌러야 관리자 대기 목록에 표시됩니다. 이전 버전 이력은 보관하지 않습니다. 파일만 올린 상태는 관리자 검토 목록에 나타나지 않습니다.

다운로드는 본인 또는 요청받은 관리자에게만 허용하며, 파일 내용은 페이지에 삽입하거나 서버에서 실행하지 않습니다. 목록에는 파일 본문을 포함하지 않습니다. 다른 학생의 파일을 조회하거나 수정할 수 없고, 학생이 파일을 교체했거나 다른 창에서 수정한 경우 오래된 피드백 저장을 거절합니다. 피드백은 최대 5,000자이며 학생에게 일반 텍스트로 표시합니다.

확인 쿼리:

```sql
SELECT project_id, user_id, filename, status, uploaded_at, requested_at, reviewed_at
FROM optional_project_submissions
ORDER BY uploaded_at DESC;
```

처음에는 0행이 정상입니다. 테스트 학생으로 업로드하면 draft, 요청 버튼을 누르면 requested, 관리자 답변 후에는 reviewed가 됩니다. 회원 삭제 시 해당 회원의 제출 기록도 삭제됩니다.
